# Architecture

A map of the code for whoever maintains it next. It explains where things live and why, not every line. Scope and business rules live in [`PROJECT.md`](../PROJECT.md). This file shows where those rules sit in the code.

## How a request flows

Every write follows the same path. Booking approval is the fullest example.

1. **Route.** `PATCH /owner/bookings/{booking}` in `routes/web.php`, inside the `auth`, `verified`, and `owner` middleware group.
2. **Middleware.** `EnsureUserIsOwner` sends users without a shop to `/owner/setup`.
3. **Controller.** `Owner\BookingController::update` finds the booking through `$user->ownerProfile->bookings()`. A booking on someone else's item is a 404, not a 403.
4. **Validation.** The target status must be a `BookingStatus` value.
5. **Action.** `ApproveBooking` checks the transition table, opens a transaction, locks the item's units, and rechecks the assigned unit with `Availability::isFree()`. If another booking took it, it swaps to `Availability::firstFreeUnit()`. If none is free it throws a `ValidationException` and the booking stays pending.
6. **Response.** The controller flashes a toast and redirects back. Inertia reloads the page props.
7. **Page.** `resources/js/components/owner/booking-actions.tsx` sent the request. Errors show under `errors.status`.

Simpler writes skip the Action and do the work in the controller, as long as it stays a few lines.

## Domain rules in code

### Statuses and transitions

Status enums own their rules. Never set a status without checking them.

- `ItemStatus::canTransitionTo()` is the full table. `ownerCanTransitionTo()` narrows it to what owners may do: publish and pause. Takedowns and review approvals go through admins.
- `BookingStatus::allowedTransitions()` maps each target status to who may set it, `owner` or `renter`. `canTransitionTo($to, $actor)` is the single check that both owner and renter endpoints use.
- `BookingStatus::blocking()` lists the statuses that hold a unit: approved and active.

To add a transition, change the enum, add a row to its dataset in `tests/Unit`, then add the button.

### Availability

`App\Support\Availability`:

- A unit is free when its status is `active` and no approved or active booking overlaps the range.
- Pending bookings never block.
- `firstFreeUnit()` picks the lowest id. Pass `lock: true` inside a transaction.

### Money

- Stored as integer centavos. ₱350.00 is `35000`.
- Converted once, in the Form Request: `ItemRequest::money()`. The marketplace price filter converts inline because it is a query, not a write.
- Money columns are never mass assigned. Controllers use `forceFill($request->money())`.
- The frontend always shows money through `formatPeso()`.

### Dates

- `start_date` and `end_date` are calendar dates. `returned_at` is a moment.
- Use `RentalDays::count()` for totals (inclusive) and `RentalDays::late()` for days late.
- The app uses `CarbonImmutable` everywhere (`AppServiceProvider`). Model doc blocks say `CarbonImmutable` to match.

### Ownership scoping

Owner routes take a plain `int $item` and resolve it through the relation, never with route model binding:

```php
$item = $request->user()->ownerProfile->items()->findOrFail($item);
```

Photos and units are then found through the item: `$item->units()->findOrFail($unit)`. Owner bookings use `OwnerProfile::bookings()`, a query builder filtered through `unit.item`.

Admin routes use normal route model binding, since admins can touch any row.

### Rows that are kept

| Row                    | Rule                             | Where                               |
| ---------------------- | -------------------------------- | ----------------------------------- |
| Category used by items | Cannot be deleted. Deactivate it | `Admin\CategoryController::destroy` |
| Item with bookings     | Cannot be deleted. Pause it      | `Owner\ItemController::destroy`     |
| Unit with bookings     | Cannot be deleted. Retire it     | `Owner\ItemUnitController::destroy` |

Foreign keys use `restrictOnDelete` as a backstop.

### Photos

- Stored on the `public` disk under `items/{item_id}/`. The row holds the path. `ItemImage` appends a computed `url`.
- Rows are written in a transaction, and files after it commits (`ItemImageController::store`).
- Deleting a photo or an item deletes its files too.
- The cover is the lowest `sort_order`, exposed as `Item::coverImage()`.

### Suspension

- `FortifyServiceProvider` refuses suspended users at password login.
- `SocialiteController::logIn` refuses them at social login.
- `LogOutSuspendedUsers` logs out anyone suspended mid session.
- `Item::scopeListed()` hides items of suspended owners. Every marketplace query starts from `Item::listed()`.

### Social login

`SocialiteController::callback` works in two modes:

- **Logged in:** it links the provider to the current user.
- **Guest:** it logs in a linked account, creates a user for a new email, or refuses an email that already exists.

`ConnectedAccountController` blocks disconnecting the last login method. It also lets users with no password set one. That form lives there, not under Security, because Security asks for password confirmation.

## How to add a feature

1. **Scope.** Check it against `PROJECT.md`. New tables or packages are a scope change.
2. **Migration.** `php artisan make:model Thing -mf --no-interaction`. Money columns `unsignedInteger`, enums from `array_column(Enum::cases(), 'value')`, `restrictOnDelete` on rows with history.
3. **Model.**
   - Add a `@property` doc block and `#[Fillable]` without status, owner, or money columns.
   - Add enum casts.
   - Add `$attributes` defaults for nullable and defaulted columns, or strict mode throws on new models.
4. **Factory.** Add states for statuses (`->status(...)`).
5. **Test first.** Write a feature test in `tests/Feature`. Cover the happy path, invalid transitions, and another user's row.
6. **Form Request and controller.** Scope owner queries through the relation. Move anything longer than a few steps into `app/Actions`.
7. **Route.** Add it to the right group in `routes/web.php`, then run `php artisan wayfinder:generate --with-form`.
8. **Page.**
   - Add `resources/js/pages/<name>.tsx` and its type in `types/models.ts`.
   - Import routes from `@/actions` or `@/routes`, never hardcoded URLs.
9. **Navigation.** Add a link in `app-sidebar.tsx` if the page needs one.
10. **Check.** Run `npm run build`, then the tests, then `composer lint`, `npx vp check --fix`, and `composer ci:check`.
11. **Commit.** Tick `BACKLOG.md` and commit per `COMMITS.md`.

## Testing

```bash
php artisan test --compact                              # everything
php artisan test --compact tests/Feature/BookingTest.php
php artisan test --compact --filter="approval swaps"
composer ci:check                                       # what CI runs
```

- Tests run on in memory SQLite (`phpunit.xml`). They never touch MySQL.
- Booking tests freeze time with `travelTo()` so date rules stay stable.
- Socialite is faked with `Socialite::fake('google', ProviderUser::fake([...]))`.
- `DatabaseSeederTest` fails if the seed data stops covering every status.

## Gotchas

- **Page tests fail with "Unable to locate file in Vite manifest".** A new page is not built yet. Run `npm run build`.
- **Wayfinder imports are missing after adding a route.** Run `php artisan wayfinder:generate --with-form`, or keep `composer run dev` running so Vite regenerates them.
- **`MissingAttributeException` on a new model.** Strict mode. Add the column to the model's `$attributes` defaults.
- **PHPStan says a property does not accept `CarbonImmutable`.** Change the doc block from `Carbon` to `CarbonImmutable`.
- **`UploadedFile::fake()->image()` fails with "GD extension is not installed".** Use `UploadedFile::fake()->create('a.jpg', 100, 'image/jpeg')`.
- **`--env=testing` does not mean the test database.** There is no `.env.testing`, so artisan commands with that flag hit the MySQL dev database. Only `php artisan test` switches to SQLite.
- **Photos do not show in the browser.** Run `php artisan storage:link` once.
- **Booking references.** `Booking` uses `HasUlids` with `uniqueIds()` returning `['reference']`, so the ULID is set on insert even when model events are off, as in the seeder. The primary key stays an integer.
- **Social only users cannot delete their account.** The delete form asks for a password. They can set one under Connected accounts first.
